## The Problem at a Glance

This is a **study-level multi-label classification** task over knee MRI examinations.

### The 12 Target Labels & Radiologist Ground-Truth Criteria

Output 12 independent **sigmoid probability scores** (NOT softmax) for each test study.  
*(Detailed clinical guidelines, physics, linguistic phrasing tables, and sequence routing matrices are documented in [`docs/CLINICAL_GUIDELINES.md`](docs/CLINICAL_GUIDELINES.md)).*

> **Golden Clinical Rule:** Ambiguous, mild, or borderline findings (*"on the fence"*) were graded as **negative (0)** by annotating MSK radiologists to favor **high specificity**.

1. **ACL tear:** High-grade partial or full-thickness tear (>50% fiber disruption/discontinuity). Mild degeneration is **0**.
2. **MCL tear:** High-grade partial or complete acute tear with edema. Low-grade sprain (Grade I/II) is **0**.
3. **Medial meniscus injury:** High signal contacting surface on **≥ 2 consecutive images** (*"2-slice rule"*) or truncation/fragment. Intrasubstance degeneration is **0**.
4. **Lateral meniscus injury:** Same 2-slice rule applied to lateral meniscus. Intrasubstance degeneration is **0**.
5. **Medial osteoarthritis:** Moderate/large area ($\ge 1\text{ cm}$) of high-grade ($>50\%$) cartilage loss in medial compartment. Mild thinning is **0**.
6. **Lateral osteoarthritis:** Moderate/large area ($\ge 1\text{ cm}$) of high-grade ($>50\%$) cartilage loss in lateral compartment. Mild thinning is **0**.
7. **Patellofemoral osteoarthritis:** Moderate/large area ($\ge 1\text{ cm}$) of high-grade ($>50\%$) cartilage loss in patellofemoral compartment. Mild thinning is **0**.
8. **Joint effusion:** Moderate/large fluid distending capsule. Trace/physiological fluid is **0**.
9. **Synovitis:** Apparent thickening/inflammation of synovial lining.
10. **Baker's cyst:** Moderate/large fluid collection in posteromedial popliteal space. Tiny bursa pouch is **0**.
11. **Bone contusion:** Impact marrow edema signal without cortical fracture line. Chronic/degenerative subchondral signal is **0**.
12. **Fracture:** Acute cortical break or discrete fracture line. Remote/healed deformity is **0**.

### Key Data Facts

- **~4,407 training studies** from 16 international institutions across 5 continents
- **Only 58 studies have explicit structured labels** — the other 4,349 must be derived from free-text radiology reports
- Reports are written in **9–12 languages** (including Arabic, French, Spanish, German, Japanese, etc.)
- Data format: **DICOM 3D MRI volumes** (sagittal, coronal, axial series), multi-series per study
- Submission: a `submission.csv` file generated by a Kaggle Notebook running offline on hidden test data (≤ 9 hours)

## Coding Conventions

### Language & Framework
- **Python 3.10+** throughout
- **PyTorch** for all deep learning (NOT TensorFlow or JAX)
- **HuggingFace `transformers`** for text models
- **`timm`** (PyTorch Image Models) for vision backbones
- **`pydicom`** + **`SimpleITK`** (or `monai`) for DICOM loading
- **`pandas`** + **`polars`** for data manipulation
- **`scikit-learn`** for cross-validation splits and AUC computation

### Code Style
- Use **type hints** on all function signatures
- Write **docstrings** (Google style) for all classes and public functions
- Keep modules **single-responsibility**: one file per concern (loader, model, loss, metric)
- No hardcoded paths — always reference paths from `config.yaml` or pass as arguments
- All random seeds must be set at the start of any training script: `torch`, `numpy`, `random`, `transformers`

### Model Output Convention
- The model's final output is always a `Tensor` of shape `(batch_size, 12)` containing **raw logits**
- Apply `torch.sigmoid()` only during inference or AUC computation — never inside the model's forward pass
- Loss: always use `BCEWithLogitsLoss` (numerically stable; works directly on logits)

### Cross-Validation Rules
- **Never use a random split** — random CV causes a **$+0.053$ artificial AUC leakage** by memorizing scanner/site fingerprints.
- Always use **Scanner Fingerprint / Site-Aware GroupKFold** (`Manufacturer` + `Model` + `Software` + `Coil` clustering).
- Target 5-fold CV; report per-fold and mean ± std macro AUC.

### Kaggle Submission Rules (Non-Negotiable)
- The submission notebook **must not download anything from the internet** at inference time
- All model weights must be attached as a Kaggle Dataset to the notebook
- The output file must be named exactly `submission.csv`
- The notebook must finish in under 9 hours on Kaggle's GPU environment
- Use `torch.cuda.amp.autocast()` for mixed-precision inference to save time

### File Categorization & Naming Rules (Production vs. Scratch/Temporary)
To maintain a clean repository and ensure full reproducibility:

1. **Production Core Files:**
   - Must reside strictly inside canonical project directories (`src/`, `scripts/`, `data/`, `notebooks/`, `docs/`, `outputs/`).
   - Must have clean, permanent names (e.g., `trainer.py`, `scan_dicom_fingerprints.py`).
   - Never contain temporary hacks or disposable exploration code.

2. **Temporary / Scratch / Debug Files:**
   - **Mandatory Prefix:** Any one-off debugging script, prompt-tuning probe, or exploratory script MUST be prefixed with `tmp_` (e.g., `tmp_inspect_batch.py`) or `scratch_` (e.g., `scratch_eval_probe.py`).
   - **Mandatory Header Docstring:** Must start with:
     ```python
     # [TEMPORARY / SCRATCH FILE — NOT FOR PRODUCTION]
     ```
   - **Root Cleanliness:** Never leave un-prefixed scratch scripts directly in the project root directory (`./`).
   - **Safe Deletion:** Any file matching `tmp_*` or `scratch_*` is explicitly disposable and can be deleted anytime without breaking the production pipeline.

## Data & Label Handling

- **Never** treat "not mentioned in report" as a reliable negative label without explicit verification
- The three-state label scheme is:
  - `1` = Report **explicitly states** finding is present
  - `0` = Report **explicitly states** finding is absent / normal / negative
  - `-1` = Report **does not address or mention** this finding at all (silence ≠ confirmed negative)
- **Ground-Truth Label Provenance (from Discussion 04 & 05 — host confirmed):**
  - `train.csv` labels (`0` and `1`) were assigned by **a panel of two independent readers with a third adjudicating reader**, working from **3D MRI image review** using the standardized research rubric — completely independently of the clinical report text.
  - A label of `0` means the finding was **evaluated and confirmed absent** (did not meet research threshold) — it does NOT mean "not annotated". This is authoritative, not a default.
  - When a clinical report and an image-derived label disagree, **the image-derived label is authoritative** and the report is wrong by competition design. This is expected and intentional (see Discussion 05 specific examples).
  - Clinical terminology in reports does NOT directly map to challenge labels: "bone marrow edema" ≠ `bone_contusion`, "chondromalacia" ≠ OA, "osteochondral fracture" ≠ `fracture`, "minimal synovitis" ≠ `synovitis = 1`. All require meeting strict image-review thresholds.
- **Bilateral Study Warning:** Both knees are occasionally scanned under one `StudyInstanceUID`. The hosts reviewed and adjusted DICOM metadata and report text for these cases to allow disambiguation. When loading studies in Phase 3, check for bilateral anatomy and parse DICOM series accordingly before routing to left/right-specific predictions.
- **Silence Semantics (post-processing after extraction):**
  - For **Synovitis** (`-1`): impute conditionally using `joint_effusion` score ($P(\text{syn} \mid \text{eff}) = 0.63$, else $0.22$)
  - For **Baker's cyst** (`-1`) and **Medial/Lateral OA** (`-1`): map to `0` (silence almost always means absence)
  - All other `-1` values: keep as `NaN` (masked in BCE loss during training — do NOT fill with 0)
- **Never call `df.fillna(0)`** on `train.csv` (this invents ~52,000 false negatives and collapses prevalence to 0.5%)
- When computing AUC, **exclude `-1` (unaddressed) samples** for that label, or use soft labels if training
- **Patient Overlap / Dedup (Kaggle Phase 3):** When working on Kaggle with full DICOM data, check for patient-level duplicates via `PatientID` DICOM tag and near-duplicate studies (same patient follow-up scans). These can inflate early CV scores — group them on the same fold side.

## Evaluation & Monitoring

- Primary metric: **Macro ROC-AUC** (mean of 12 individual AUCs) — this is the Kaggle leaderboard metric
- Always log **all 12 per-label AUCs** in addition to the macro average
- Do NOT optimize a classification threshold — predict calibrated scores, not hard labels
- Watch for rare-label collapse (fracture, bone contusion AUC near 0.5 = the model is guessing)

### 58 Gold Studies — Governance Rules
- **At n=58, differences below ~0.02 macro AUC are statistical noise.** Do not treat small deltas as meaningful signal.
- **Do NOT repeatedly tune extraction prompts against the 58 gold studies** — this is label-extraction overfitting. Run the validation check **once** after Phase 2 extraction is complete.
- Plan downstream utilization of the 58 gold studies: use them for **loss upweighting** in the image model or a **Platt scaling / temperature calibration pass** after training — do NOT hold them out entirely.

This is the structural ceiling — not a bug. Do NOT target 90%+; reaching 83–85% is effectively best-in-class performance.

## Phase 3 DICOM Series Routing Rules (Physics-First)

When the image pipeline classifies DICOM series by sequence type and plane, use MRI physics parameters **first** and `SeriesDescription` text **second**:

| Classification | Primary Signal (Physics) | Secondary Signal (Text Regex) |
|---|---|---|
| **Fluid-Sensitive vs. Anatomical** | `EchoTime (TE)` > 30ms → likely T2/fluid-sensitive; low TE + low TR → T1 | `SeriesDescription` keywords (T2, PD_FS, STIR, T1) as a confirmation vote only |
| **Plane (Sagittal/Coronal/Axial)** | `ImageOrientationPatient` DICOM tag (most reliable) | `SeriesDescription` text plane keywords as secondary |

**Reason:** Radiographers at 16 international institutions use wildly inconsistent `SeriesDescription` abbreviations across languages and vendors. Physics tags are standardized across all scanners.

**Action after routing:** Spot-check a random sample of 20 routed series visually in Phase 3 before training on top of them. A systematic routing error silently corrupts all downstream model training.

## Report vs. Image Label Design — Structural Gap (Discussions 04 & 05)

This section documents a core design choice in the competition that directly affects Phase 2 strategy and Phase 4 multimodal fusion architecture.

### The Two Independent Generative Processes

| Source | How Created | Reliability |
|---|---|---|
| **Clinical Report** | One signing radiologist, routine clinical care, any language, subjective phrasing | Noisy — may contain ambiguities, internal contradictions, threshold mismatches |
| **Ground-Truth Label** | Two independent readers + third adjudicating reader, standardized 3D MRI image review rubric | Authoritative — strict threshold criteria, designed for high specificity |

**Key Implication:** The two processes produce different outputs for the same study. This is **by design, intentional, and expected.** The host confirmed both in Discussion 04 and Discussion 05.

### Confirmed Clinical Terminology Mismatch Examples (Discussion 05 Audit)

These are real cases from the 58 gold studies where report text and image label disagree:

| Report Says | Image Label | Clinical Reason |
|---|---|---|
| "Synovitis of left knee and massive joint effusion" | `Effusion = 1`, **`Synovitis = 0`** | Marked effusion without synovial hypertrophy meeting research threshold |
| "Leve derrame articular con mínima sinovitis" (Mild joint effusion with minimal synovitis) | **`Effusion = 0`**, **`Synovitis = 0`** | Mild/minimal findings graded 0 to enforce high specificity |
| "There is a mild knee effusion." | **`Effusion = 0`** | Trace/physiological fluid graded 0 |
| German: "Baker-Zyste" (Baker's cyst) | **`Baker's = 0`** | Small incidental bursa below size threshold |
| "OA femorotibial medial y lateral. OA patelofemoral." | **`Medial OA = 0`**, **`Lateral OA = 0`**, `PF OA = 1` | Tibiofemoral cartilage loss did not reach >1cm / >50% threshold |
| Turkish: "Lateral menisküs normal" (Lateral meniscus normal) | **`Lateral meniscus = 1`** | 3-reader panel identified definite visual tear missed in routine prose |
| "Patellar chondropathy" (no synovitis mention) | `PF OA = 1`, **`Synovitis = 1`** | Synovitis visible on MRI despite clinical omission in report |
| Bulgarian: osteochondral fracture described | **`Fracture = 0`** | Osteochondral impaction without acute cortical fracture line |

### Implications for Phase 2 (NLP Extraction)
- **~82.5% is the structural ceiling** for report-only label agreement — not a model failure. Chasing higher accuracy means the model is memorizing report patterns that contradict ground truth.
- The hardest labels to extract correctly from text: **Synovitis**, **any OA grade**, **Contusion**, **Baker's cyst** (all have strict image-threshold criteria that clinical language consistently misclassifies).
- Prompt engineering should encode the clinical thresholds (size, severity, extent) — the existing Clinically Calibrated Prompt below does this correctly.

### Implications for Phase 4 (Multimodal Fusion)
- **NLP-extracted pseudo-labels are noisy supervision** — treat them as soft labels, not hard targets.
- **Image model outputs should dominate late fusion** — the image is closer to the authoritative label process than the report.
- When training a text encoder (XLM-RoBERTa), apply **higher label smoothing** on pseudo-label samples and **lower label smoothing** on the 58 gold studies.

## LLM API Usage & Clinically Calibrated Prompt Template

- Permitted by official competition rules (Section 2.6.b and the hosts' LLM clarification post)
- Preferred API: **Google Gemini** (Flash or Pro for cost-efficiency)
- **Clinically Calibrated Extraction Prompt:**
  ```
  You are an expert subspecialty musculoskeletal (MSK) radiologist. Read the following knee MRI radiology report (written in any language) and extract the exact clinical status for each of the 12 target findings below.

  CRITICAL ANNOTATION RULES (Follow the official RSNA Radiologist Ground-Truth Guidelines):
  1. Golden Rule: Borderline, mild, or ambiguous findings MUST be labeled as 0 (favor high specificity).
  2. acl_tear: 1 ONLY if high-grade partial (>50% fibers disrupted) or full-thickness tear / rupture. Mild degeneration or intact reconstruction = 0.
  3. mcl_tear: 1 ONLY if high-grade partial or complete tear. Low-grade sprain (Grade 1/2) or remote thickening = 0.
  4. medial_meniscus: 1 ONLY if tear contacts articular surface or shows displacement/flap/bucket-handle. Intrasubstance degeneration = 0.
  5. lateral_meniscus: Same criteria as medial meniscus. Intrasubstance degeneration = 0.
  6. medial_oa: 1 ONLY if moderate-to-severe (>1cm area with >50% cartilage thickness loss). Mild thinning = 0.
  7. lateral_oa: Same criteria as medial OA. Mild thinning = 0.
  8. patellofemoral_oa: Same criteria as medial OA. Mild thinning = 0.
  9. joint_effusion: 1 ONLY if moderate or large fluid distension. Trace or physiological fluid = 0.
  10. synovitis: 1 ONLY if marked synovial thickening or inflammatory hypertrophy is described.
  11. bakers_cyst: 1 ONLY if moderate or large popliteal cyst. Tiny incidental bursa fluid = 0.
  12. bone_contusion: 1 ONLY for traumatic marrow edema / impact contusion. Chronic degenerative OA edema = 0.
  13. fracture: 1 ONLY for acute cortical fracture line. Healed remote fracture = 0.

  OUTPUT FORMAT: Output ONLY a valid JSON with these EXACT numeric values:
    1  = The report EXPLICITLY states this finding is present / positive.
    0  = The report EXPLICITLY states this finding is absent / normal / negative.
   -1  = The report does NOT address or mention this finding at all (silence / unaddressed).
  (Do NOT use 0 for silence — use -1. Reserve 0 only for explicit negations.)
  {
    "acl_tear": 0,
    "mcl_tear": 0,
    "medial_meniscus": 0,
    "lateral_meniscus": 0,
    "medial_oa": 0,
    "lateral_oa": 0,
    "patellofemoral_oa": 0,
    "joint_effusion": 0,
    "synovitis": 0,
    "bakers_cyst": 0,
    "bone_contusion": 0,
    "fracture": 0
  }

  Radiology Report:
  {report_text}
  ```
- Rate limit the API calls; process in batches with exponential backoff
- Cache API responses to disk in `data/labels/` — never re-call the API for the same report
